# JunoClaw Prover Daemon

Runs on the robot (or edge device). Generates ZK safety proofs from sensor data and submits them on-chain.

## Architecture

```
ROS2 Bridge (HTTP) → Prover Daemon → ZK Proof → On-chain Submit
                         |
                    Circuit Breaker Check
```

## Quick Start

### 1. Setup keys (one-time)

```bash
cargo run -- setup --output ./keys --tree-height 7
```

### 2. Start the ROS2 bridge (in simulation mode)

```bash
# In another terminal
junoclaw-ros2-bridge --robot-id warehouse-bot-01 --simulate --port 8080
```

### 3. Generate a proof (one-shot)

```bash
cargo run -- prove \
  --bridge-url http://localhost:8080 \
  --batch-id batch_42 \
  --robot-id warehouse-bot-01 \
  --keys-dir ./keys \
  --output proof.bin
```

### 4. Verify the proof locally

```bash
cargo run -- verify \
  --vk ./keys/sensor_verifying_key.bin \
  --proof proof.bin \
  --public-inputs '["0x123...", "0x456...", "0x0"]'
```

### 5. Submit on-chain

```bash
cargo run -- submit \
  --chain-rpc http://localhost:26657 \
  --verifier-addr juno1qd9qaggnw350kt7wjpw37h0c7666wuwulhz0makrve9tenkx0ymqvfkh7p \
  --proof proof.bin \
  --vk ./keys/sensor_verifying_key.bin \
  --public-inputs '["0x123...", "0x456...", "0x0"]'
```

### 6. Run as a daemon (continuous mode)

```bash
cargo run -- run --config prover-config.toml --interval 10
```

## Configuration

Create `prover-config.toml`:

```toml
robot_id = "warehouse-bot-01"
bridge_url = "http://localhost:8080"
chain_rpc = "http://localhost:26657"
keys_dir = "./keys"
verifier_addr = "juno1qd9qaggnw350kt7wjpw37h0c7666wuwulhz0makrve9tenkx0ymqvfkh7p"
circuit_breaker_addr = "juno1..."
safety_envelope_addr = "juno1..."
merkle_verifier_addr = "juno1..."
poll_interval_secs = 10
log_level = "info"
```

## Commands

| Command | Description |
|---------|-------------|
| `setup` | Generate proving/verifying keys for all circuits |
| `prove` | Generate a single proof from a batch ID (one-shot) |
| `verify` | Verify a proof locally before submitting |
| `submit` | Submit a proof on-chain to the zk-verifier contract |
| `run` | Run as a continuous daemon |

## Daemon Loop

1. Poll ROS2 bridge for new reflex batches
2. Build Merkle tree from cycle hashes
3. Generate SensorSafety proof (~80ms)
4. Submit proof on-chain via zk-verifier contract
5. Check circuit breaker state
6. Sleep until next polling interval

## Performance

| Operation | Time |
|-----------|------|
| SensorSafety proof | ~80ms |
| IntentConsistency proof | ~119ms |
| ConsensusMembership proof | ~51ms |
| Aggregation proof | ~68ms |
| **Total (parallelized)** | **~187ms** |
| On-chain verification | ~13ms |

## Requirements

- Rust 1.78+
- Proving/verifying keys (generated by `setup` command)
- ROS2 bridge running (or simulation mode)
- Chain RPC endpoint (for on-chain submission)
