Anatomy of finality

One certificate. Two kinds of math. One state root.

Fast chains often certify the order of transactions first and attest to state later. A JunoClaw certificate covers the result.

01

Execute

Deterministic KV + CosmWasm execution produces a Merkle state_root, which goes into the block payload.

02

Vote twice

Each validator signs with a BLS12-381 threshold partial and a 186-byte MAYO2 signature.

03

Certify

The certificate needs a quorum on both halves. Breaking one scheme isn't enough to forge it.

04

Chain-link

Each certificate binds the previous one, so light clients verify a certificate chain instead of header chains.

The chain

Small enough to audit. Strict enough to trust.

Not a Cosmos SDK fork and not a Tendermint derivative. It's a lean Rust chain on Commonware's consensus, broadcast and storage primitives.

Instant, deterministic

No confirmations, no reorgs, no probabilistic settlement. When a block is final, it's final.

Fail-stop, not fork

A node that computes a different state halts loudly. Proposals with a wrong height, parent, root or size are rejected.

Self-healing sync

Height-range backfill and certified state-sync with a multi-peer anchor quorum. Wiped nodes rejoin on their own.

Familiar interfaces

CosmWasm contracts and Cosmos-style gRPC: BroadcastTx, GetTx, Simulate.
