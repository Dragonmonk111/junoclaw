# JunoClaw SDK — Integration Guide for Robotics Firms

This document describes how a robotics firm integrates JunoClaw into their robot stack.

## Two Integration Paths

### Path A: Full Integration (Rust + Python)

For firms with a Rust toolchain or the ability to run Rust binaries on their robot:

```
Robot Controller (ROS2) → junoclaw-ros2-bridge (Python) → junoclaw-prover (Rust) → Juno Chain
```

**Install:**
```bash
# Python bridge (on robot or edge device)
pip install junoclaw-ros2-bridge

# Rust prover daemon
cargo add junoclaw-prover
# or use pre-built binary from releases
```

### Path B: Bridge-Only Integration (Python only)

For firms that want to use JunoClaw's on-chain verification without running the Rust prover:

```
Robot Controller (ROS2) → junoclaw-ros2-bridge (Python) → HTTP API → Juno Chain
```

**Install:**
```bash
pip install junoclaw-ros2-bridge
```

The bridge exposes HTTP endpoints that any HTTP client can call. The prover daemon is optional — proofs can be generated by any service that wraps the circuit crates.

## Python SDK: junoclaw-ros2-bridge

### Installation

```bash
pip install junoclaw-ros2-bridge
```

### Usage as a Library

```python
from junoclaw_ros2_bridge.server import Ros2Bridge, IntentResult, BatchResult

# Create bridge instance
bridge = Ros2Bridge(robot_id="my-robot-01", simulate=False)

# Store an intent from your action server callback
intent = IntentResult(
    robot_id="my-robot-01",
    action="navigate",
    params={"target_x": 12.5, "target_y": 8.3},
    sensor_snapshot=base64.b64encode(sensor_data).decode(),
    controller_timestamp=int(time.time() * 1000),
    rationale="navigate to loading bay 3",
    execution_proof_ref="rosbag2_2026_08_19/batch_42",
)
intent_id = bridge.store_intent(intent)

# Store a reflex batch
batch = bridge.generate_simulated_batch(cycle_count=1000, violate=False)
bridge.store_batch(batch)
```

### Usage as a Server

```bash
junoclaw-ros2-bridge --robot-id my-robot-01 --port 8080
```

### ROS2 Integration

The bridge subscribes to standard ROS2 topics:

| Topic | Type | Usage |
|-------|------|-------|
| `/cmd_vel` | `geometry_msgs/Twist` | Velocity commands for sensor snapshot |
| `/scan` | `sensor_msgs/LaserScan` | LiDAR for collision distance |
| `/imu` | `sensor_msgs/Imu` | IMU for tilt/orientation |

To add custom topics, subclass `Ros2Bridge` and override the callbacks.

## Rust SDK: junoclaw-prover

### Installation

```toml
[dependencies]
junoclaw-prover = { path = "../prover-daemon" }
```

### Usage as a Library

```rust
use junoclaw_prover::{BatchResponse, prove};

// Fetch batch from bridge
let batch: BatchResponse = reqwest::get("http://localhost:8080/rosbag/batch_42")
    .await?.json().await?;

// Generate proof
let proof_bytes = prove::generate_sensor_proof(
    std::path::Path::new("./keys"),
    &batch,
    "my-robot-01",
)?;

// Submit on-chain
submit::submit_proof_raw(
    "http://localhost:26657",
    "juno1...",
    &proof_bytes,
    std::path::Path::new("./keys"),
).await?;
```

## On-Chain Contract Integration

### Query Safety Envelope

```bash
junoclay query safety-envelope get-envelope --robot-id my-robot-01
```

```json
{
  "robot_id": "my-robot-01",
  "params": {
    "max_speed_milli": 2000,
    "max_force_milli": 50000,
    "min_collision_distance_milli": 500,
    "max_tilt_milli_degrees": 15000,
    "max_acceleration_milli": 3000,
    "human_proximity_allowed": false
  },
  "version": 1,
  "updated_at": 1724073600,
  "updated_by": "juno1..."
}
```

### Set Safety Envelope (Governance)

```bash
junoclay tx safety-envelope set-envelope \
  --robot-id my-robot-01 \
  --max-speed 2000 \
  --max-force 50000 \
  --min-distance 500 \
  --max-tilt 15000 \
  --max-accel 3000 \
  --human-proximity-allowed false
```

### Check Circuit Breaker

```bash
junoclay query circuit-breaker is-locked --robot-id my-robot-01
```

### Submit ZK Proof

```bash
junoclay tx zk-verifier verify-proof \
  --proof proof.bin \
  --verifying-key sensor_verifying_key.bin \
  --public-inputs '["0x...", "0x...", "0x0"]'
```

## Custom Robot Integration

### Step 1: Define Safety Envelope

Map your robot's safety parameters to the JunoClaw envelope schema:

```python
ENVELOPE = {
    "max_speed_milli": 2000,        # 2.0 m/s
    "max_force_milli": 50000,       # 50 N
    "min_collision_distance_milli": 500,  # 0.5 m
    "max_tilt_milli_degrees": 15000,      # 15 degrees
    "max_acceleration_milli": 3000, # 3.0 m/s²
    "human_proximity_allowed": False,
}
```

### Step 2: Configure Bridge

```bash
junoclaw-ros2-bridge \
  --robot-id my-robot-01 \
  --sensor-topics /cmd_vel,/scan,/imu,/joint_states \
  --action-servers navigate,pick_object,place_object \
  --port 8080
```

### Step 3: Start Prover Daemon

```bash
junoclaw-prover run \
  --config prover-config.toml \
  --bridge-url http://localhost:8080 \
  --chain-rpc http://chain:26657 \
  --interval 5
```

### Step 4: Monitor

```bash
# Bridge health
curl http://localhost:8080/health

# Prover logs
docker logs -f junoclaw-prover

# Chain state
junoclay query circuit-breaker is-locked --robot-id my-robot-01
```

## Supported Robot Platforms

| Platform | ROS2 Compatible | Integration Path |
|----------|----------------|-----------------|
| Unitree G1/H1 | Yes (ros2 unitree_ros) | Path A or B |
| Boston Dynamics Spot | Yes (spot_ros2) | Path A or B |
| TurtleBot 3/4 | Yes (native ROS2) | Path A or B |
| Universal Robots | Yes (ur_robot_driver) | Path A or B |
| Custom robots | If ROS2-compatible | Path A or B |
| Non-ROS2 robots | Via HTTP bridge API | Path B (direct HTTP) |

## API Reference

### Bridge HTTP API

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/health` | GET | Bridge health check |
| `/intent/{id}` | GET | Fetch intent result |
| `/intent/simulate` | POST | Generate simulated intent |
| `/rosbag/{id}` | GET | Fetch reflex batch |
| `/rosbag/simulate` | POST | Generate simulated batch |
| `/robot/register` | POST | Register robot metadata |

### Prover CLI

| Command | Description |
|---------|-------------|
| `setup` | Generate proving/verifying keys |
| `prove` | Generate a single proof |
| `verify` | Verify a proof locally |
| `submit` | Submit proof on-chain |
| `run` | Run as continuous daemon |
